**Important Issues I Noticed**
The biggest functional risk: backend schema/mapping uses fully qualified SAP names like `KNA1.KUNNR`, while later frontend pipeline logic expects bare names like `KUNNR`. That can break extraction, harmonization, validation, transformation, and DMC export because records may be keyed by `STRUCT.FIELD` but validators/exporters look for `FIELD`.

Another real bug: frontend calls `/api/sap/map/correct`, but I did not find a backend route implementing that endpoint.

Auth is incomplete: the UI stores Supabase tokens and sends `Authorization`, and [backend/dependencies.py](/d:/project-2-sap-migration-studio/SAP-Migration-Studio/backend/dependencies.py) can validate JWTs, but the routers don’t actually use that dependency. Project and mapping APIs currently use the service-role client without user ownership separation.

Docs are stale: README is still the default Vite README, and the in-app tech docs describe “Vanilla JS”, “Zero Dependencies”, and “Claude AI”, which no longer matches this React/FastAPI/Gemini-Groq-OpenRouter codebase.

There are tracked `__pycache__` files, plus an untracked `backend/venv/`; those should usually stay out of git.
